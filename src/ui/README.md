# ui

Reusable DOM components (classes with `dispose()`):

- `VirtualList` — the one virtualization primitive (fixed rows, recycled elements).
- `Tree` — lazy tree on VirtualList with ARIA tree semantics; `treeParts.ts` holds its keyboard
  navigation, selection model (set + anchor + focused row) and VS Code-style sticky ancestor rows.
- `QuickInput` — palette-style picker and single-line prompt. Rows can start a group
  (`separator`: a line and the group's name at the right); `pickDynamic`'s `alternate` handles
  Ctrl/Cmd+Enter (to the side, closes) and → at the end of the text (in the background, stays).
  `pick`'s `onActive` hears the active row change (Paste from history previews it, D393).
  `openSession(kind, props, handlers)` is a live session (VS Code's QuickPick / InputBox):
  Enter reports `accept` and it stays open; `update` changes items, busy (the progress line),
  title / step / buttons (Back at the left), item buttons, checkboxes (canSelectMany), the value
  and a validation message (only Error holds Enter) while it's open; `hide` comes once. The
  filtering and active-row rules are DOM-free in `quickInputModel.ts` (tested).
- `Menu` — menus and context menus (§12.5): hover submenus, disabled and checked items, ←/→.
- `Notifications` (toasts, §12.11), `Dialog` (modal dialogs, §12.10; `signal` closes one that was
  answered elsewhere; `isModalDialogOpen()` stops keybindings under one, D203), `Sash` (resize handle),
  `Icon` (Lucide sprite), `Tooltip` (§12.8: `setTooltip(el, label, command?)`, `ariaLabel: false`
  for recycled list rows, + one global
  `Tooltips` manager), `HoverCard` (`HoverCards`: an interactive card beside a hovered target,
  built per target, D148), `Logo`.
- `relativeTimes.ts` — relative times that stay current: an element with `timeAttrs(time)`
  (`data-time`) under a root given to `keepTimesCurrent(root, format)` gets its text rewritten by
  one shared minute timer (only while the window is visible and the root on screen; a root laid
  out again is brought up to date). `refreshTimes(root)` for a view's `onShow`.
- `fuzzy.ts`, `fileTint.ts` — DOM-free, tested.
- `markdown/` — Markdown for chat answers and previews (DESIGN.md §14): `parse.ts` builds a small
  tree (headings, paragraphs, fenced code, nested lists, quotes, rules, GFM tables, math; inline
  code, bold, italic, links, `$math$`) and copes with unfinished streaming input; `render.ts` makes
  DOM nodes with `textContent` only (no innerHTML), links limited to http(s)/mailto, code blocks
  with a copy button. `visuals.ts` (D172) draws ```mermaid with pele and TeX with KaTeX (MathML),
  both lazy chunks, cached, the diagram's SVG cleaned before it's inserted and redrawn for its
  width; `RenderOptions.visuals: false` shows them as code. `sanitize.ts` (D210, DOM-free,
  tested) is raw HTML's allowlist sanitizer: a CommonMark tag tokenizer, tag / attribute /
  URL rules (http(s), mailto, data:image, relative files; no handlers, styles, scripts, frames,
  forms, SVG; ids as `data-anchor`) and a builder that nests inline tags (`# <img …>`,
  `<a href>…</a>`) and HTML blocks into a `SafeNode` tree that `render.ts` turns into fresh
  elements. Unknown tags in prose ("Vec<T>") stay text. D218: HTML blocks go through
  `SafeHtmlWriter` (clean HTML text: kept tags with checked, escaped attributes; Markdown blocks
  between HTML blocks as `data-md-slot` placeholders) and `htmlTree.ts` (an inert DOMParser for
  HTML's full tree rules, its tree checked again through `cleanTag`; the builder where there's no
  DOMParser). `render.ts` `blockList` runs an HTML block that leaves elements open together with
  the Markdown after it, so `<details>` + blank line + Markdown + `</details>` nests as on GitHub.
  D229: inline HTML in a paragraph goes the same way (`SafeHtmlWriter({ inline: true })`: span
  slots, unknown tags as text), so `<b>a<i>b</b>c</i>` nests as the browser's parser has it.

`icons/sprite.svg` is generated by `scripts/build-icons.mjs` (only the icons listed there).

`Menu`: menus are at most min(70vh, 520px) tall and scroll; `MenuOptions.search` /
`MenuItem.searchable` add a search box that filters items (D87). `MenuOptions.minWidth` and
`flush` make a dropdown's list: as wide as its field, just under it, and when it doesn't fit,
on the side with more room, shortened (D282).

`SelectMenu.ts` (D282): `installSelectMenus(doc)` makes every single-choice `<select>` in a
document open the IDE's menu instead of the system's list (installed for the main window and each
auxiliary window); picking fires `input` and `change`. `selectMenuItems` maps the options.
`data-native-select` on a field keeps the system list.

`Tree` (D200): a click on empty space or Escape clears the selection; a right-click below the rows
fires `onContextMenu` with `item: null`. With `TreeDataSource.label`, typing moves to the next
row starting with the typed letters, and `setFind(query, filter)` / `findNext` / `findCount`
highlight or filter the shown rows (`treeFind.ts`, DOM-free, tested).

`Tree` (D201): `TreeDataSource.opensWithChildren(item)` — an item with children that opens like a
leaf (a file with nested files): only a click on an element with `data-tree-twistie` in its row
toggles it, Enter opens it, and its children are read again with its parent's;
`startsExpanded(item)` for items that show expanded when first listed. A node isn't forgotten by
its old parent's refresh once another parent lists it.
